# 大方向

> 项目的一份「地图」——不写实现细节，只讲方向和取舍。写代码时该看什么、该做什么，读这一份就够了。

## 我们做的是什么

一个**在浏览器里打开即玩**的视觉小说（VN）。不需要安装、不需要登录，点开链接就是完整作品。

它是**剧情和演出的载体**：故事、角色、画面、音乐共同构成体验。技术只是把体验送达玩家的手段，不是目的。

## 三个支柱

1. **剧本驱动**：故事本身是数据（剧本）。内容创作者写剧本，引擎负责演。改剧情不动程序，加场景不加代码——这是这个项目的根基，任何发展都不能背离它。
2. **内容为核**：项目的价值在于 77 个（并不断增长的）剧情场景、角色、画面。玩家记的是故事，不是引擎。
3. **纯浏览器**：网页是唯一形态。秒开、可外链、随处分享。不做安装包，不依赖任何本地环境。

## 目标与取舍

- **主线目标**：让玩家能从头到尾流畅地玩完一部完整作品——看剧情、做选择、解锁回想、来回存档读档。体验顺滑不卡壳，比功能多更重要。
- **演出出彩**：画面（背景/CG/立绘）、转场、镜头、音频、视频这些「演」的部分持续打磨，让剧情更有感染力。
- **内容迭代优先**：引擎能力已基本够用。之后的大部分精力应放在新剧本、新场景、翻译打磨上，而不是再造新功能。
- **明确不做**：编辑器、插件市场这类开发工具生态——那是远期甚至不做的方向。我们服务玩家，不是服务开发者。

## 内容方向

- 三条故事线（角色：azusa / iru / isekai）并行推进，各自拥有独立的场景集。
- 成人向内容，译文要求**生动、自然、多变**：整句意译、拟声词依语境处理、不机械套模板。
- 回想系统承担「收集感」：通关解锁，让玩家有回味的动力。

## 品质原则

- **顺畅优先**：加载不卡、切图不黑屏、操作即时响应。任何「卡一下」都是缺陷。
- **内容可迁移**：剧本是纯数据，换平台、换引擎、换界面都能带走——这是对内容的长期投资。
- **永远以线上的实际效果为准**：本地再完善，也要到部署后的真实页面去验收。

## 现在的方向

- 稳住引擎（已基本完备），**把注意力转回内容和演出**。
- 把 77 个场景的内容质量、翻译、演出效果做到位。
- 保持文档干净、仓库干净，让任何接手的人能马上理解「这是什么、往哪走」。
